# Референсы и инструменты

## Где искать

| Что нужно понять | С чего начать |
|---|---|
| Текущая визуальная система | Скриншоты, макеты, шаблон презентации и компоненты пользователя. Для внутреннего инструмента захвати несколько реальных состояний. |
| Композиция публичного сайта | [Inspo](https://inspomcp.dev/), [Awwwards](https://www.awwwards.com/), живые сайты из той же категории. |
| Сценарии работы в интерфейсе | [Mobbin](https://mobbin.com/), доступные реальные продукты. Смотри последовательность экранов и переходы между состояниями. |
| Типографика и детали графики | [Dribbble](https://dribbble.com/) и предшествующие материалы бренда. Смотри конкретную секцию, подпись или раскладку, которая решает похожую задачу. |
| Слайды и питчи | Материалы автора или организации, чей шаблон используется. Для стартап-питчей — [примеры и критерии YC](https://www.ycombinator.com/library/4T-how-to-design-a-better-pitch-deck). |
| Анимация и переходы | Живой сайт из Awwwards или публичное видео. Сохрани фрагмент и отметь начальный кадр, последовательность изменений и длительность. |

Запрос начинай с формата, действия пользователя и искомого приёма. Пример — «мобильные шаги подтверждения заказа, где видны сумма и условия». Фиксируй URL или имя файла, часть экрана и наблюдение, полезное для задачи. Для сложной работы разумная подборка может насчитывать 9–12 разных кадров, если каждый добавляет свой ответ. Для локальной правки достаточно текущего рендера. Из частных материалов выноси в общий Hub только разрешённые к повторному использованию выводы.

## Захват и сравнение

- Для UI используй доступный браузер, его снимки или проектный Playwright. Сними тот же размер, состояние, масштаб и область до и после. Используй текущий рендер слайдов или PDF, если это документ. Для motion сравни кадры по таймкодам.
- В Inspo MCP вызови `search_screens` с коротким запросом или `recommend` с публичным описанием задачи. Открой подходящие карточки через `get_screen` и сравни desktop и mobile. Если сервер недоступен в сессии, открой тот же архив в браузере. [Inspo MCP](https://inspomcp.dev/mcp).
- [Awwwards MCP](https://github.com/Gsta/awwwards-mcp) — независимый инструмент из экосистемы Awwwards. Если он уже подключён, используй его `search_sites` и `search_elements` для поиска. Если его нет, пользуйся галереей Awwwards и живыми сайтами.
- Если Agent Browser уже доступен, его захват и запись пригодятся для сайтов с движением. Для обычной проверки достаточно встроенного браузера или имеющейся проектной конфигурации. [Agent Browser](https://github.com/vercel-labs/agent-browser).

Для нескольких пар снимков используй [оригинальный скрипт Cook](../../../vendor/cook/scripts/side-by-side.mjs). Слева референс, справа текущий рендер. Для каждой пары используй одинаковую область и подходящее соотношение сторон. Полные скриншоты сравнивай фрагментами, если на общей картинке теряется читаемость.

На Windows запусти [обёртку Cook](../../../tools/Invoke-CookComparison.ps1) из корня Hub. Подставь существующие входные файлы и новый выходной путь. Cook перезаписывает файл по указанному пути. Обёртка задействует FFmpeg только на время вызова. Тяжёлые файлы сравнения храни на D:.

```powershell
& ./tools/Invoke-CookComparison.ps1 --out 'D:/DrawingAI_runs/site-date/compare.png' 'D:/DrawingAI_runs/site-date/reference.png' 'D:/DrawingAI_runs/site-date/current.png' --aspect 16:9
```

На машине с Node.js 18+ и `ffmpeg` в `PATH` можно напрямую вызвать `node vendor/cook/scripts/side-by-side.mjs --help`.

На этом компьютере локальная сборка FFmpeg 9.1 и FFprobe лежит в `D:/DrawingAI_runs/design-hub-tools-2026-11-22/ffmpeg-9.1-essentials_build/bin`. [Источник сборки](https://www.gyan.dev/ffmpeg/builds/#release-builds).

## Impeccable

Перед сдачей веб-дизайна запусти `detect` из корня целевого проекта на изменённых файлах. Если веб-страница уже запущена и доступна используемому браузеру, проверь её адрес в целевых размерах. Сканирование исходников проверяет CSS и разметку. Сканирование URL видит фактические размеры, контраст и переполнения. [Документация детектора](https://impeccable.style/docs/detector/) · [Каталог признаков](https://impeccable.style/slop/).

На этом компьютере используй [обёртку Design Hub](../../../tools/Invoke-Impeccable.ps1) для Windows. Выполняй команду из корня целевого проекта. Подставь путь к изменённому файлу или локальный адрес проекта.

```powershell
$detector = '<абсолютный путь к Design Hub>/tools/Invoke-Impeccable.ps1'
& $detector detect --json 'src/components/Card.tsx'
& $detector detect --viewport 390x844 --json 'http://localhost:3000'
```

Если PowerShell отказывается запускать `.ps1` («выполнение сценариев отключено»), например в песочнице Codex, используй [запуск через Python](../../../tools/impeccable.py) с теми же аргументами. Он задаёт те же переменные и вызывает тот же движок. Политику выполнения не меняй.

```powershell
python '<абсолютный путь к Design Hub>/tools/impeccable.py' detect --json 'src/components/Card.tsx'
```

На других машинах используй имеющийся `impeccable detect` или команду из официальной документации. Код `2` означает найденные проблемы, `1` — ошибку проверки, `0` — завершённую проверку без основных замечаний. Сверяй срабатывания с рендером, заданием и утверждённым стилем. Если детектор недоступен, проверь рендер по локальному чеклисту. Для презентаций, документов и нативных интерфейсов используй [проверки своего формата](quality.md).

Скилл, полный комплект и другие команды описаны в [справочнике Impeccable](impeccable.md).
